## 4. Apple architecture (verified)

- `BethanyKit` (no UI): `APIClient` (actor, bearer from Keychain), `AuthService`
  (password → 2FA verify/setup), `SessionStore` (permissions, idle policy,
  token renewal), `Permissions` / `NavCatalogue` (the console sidebar, pinned by
  `NavCatalogueTests`), `Navigation` (`Route`, 112 cases), `Money` (no `+`;
  clients never sum or convert), `OfflineStore`, `Realtime`, `PushRegistration`
  (`push/subscribe-device`, APNs), `PasskeyStepUp`, `Kiosk`, `LocationService`,
  `Approvals` (this branch).
- `BethanyUI`: `Shell/` — `MacShell` (sidebar, command palette),
  `MobileShell` (tab bar on iPhone, sidebar split view on iPad by size class),
  `RouteView` (gate → native screen → **`ConsoleBridgeView` fallback**),
  `AppEnvironment`; `Features/` — 83 files, 102 `FeatureRegistry.register` calls.
- **Web fallback, stated plainly:** a route with no registered native screen
  renders the console page in a web view (`ConsoleBridgeView`). On 2026-11-10
  exactly one `Route` case uses it: `handoff(id:)` (the shipment handoff page).
  Bridged routes are never counted as converted in the parity matrix.
- macOS and iPadOS share every feature file; they differ only in shell
  (`MacShell` vs `MobileShell`) and in `#if os(...)` file handling. The matrix
  tracks them separately all the same, because neither has been built in Xcode
  or run on a device from this environment.
- Swift source: 121 files, ~35,600 lines (`find apple -name '*.swift'`).

## 6. Money and security rules the apps inherit

Clients display the Hub's figures and never compute money (`Money` has no
arithmetic). Recognised sales, settled payments, reporting rates and outlet
scope are server-side (`MetricEngine`, `SettledPayment`, `ReportingCurrency`,
`ViewerScope`). Every native action is gated by the same permission slug the
server checks; the server's check is the one that counts. No credentials,
secrets or tokens are embedded in the apps; the bearer token lives in the
Keychain (Apple) and `SecureStore` (Android, `android/core`).
